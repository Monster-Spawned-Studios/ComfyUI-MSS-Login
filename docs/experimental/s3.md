# S3 storage (experimental)

## What it does

Mounts or syncs models (and optionally workflows) to an S3-compatible bucket (AWS S3, Backblaze B2, MinIO, etc.). Model downloads can target S3 via `destination_type: "s3"`.

## How to enable

- Master: `EXPERIMENTAL_FEATURES=true`
- Feature: `experimental.s3: true` or `EXPERIMENTAL_S3=1`
- Configure bucket/endpoint in **MSS-Login → S3 Settings** (owner) or `config.json` → `s3_storage`
- Role permission: `can_access_s3_storage`

Credentials: env (`S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY`) **or** Fernet-encrypted keys in the users DB (never plaintext in `config.json`).

## When it is required

Required for S3 destinations in the model downloader, S3 admin APIs, and workflow sync to object storage. Without FUSE/s3fs, MSS-Login uses **boto3 mode** (Linux/Windows/WSL2/macOS). FUSE mount is preferred on Linux/WSL2 when available; macOS FUSE is optional and not required.
